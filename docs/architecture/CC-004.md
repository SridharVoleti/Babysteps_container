# CC-004 — Container Extension Model

Status: APPROVED / FROZEN requirement implementation.

## Invariant
Learning apps extend the shared Consumer App Container only through approved, versioned extension points. Container core is not modified, copied, monkey-patched or forked per app.

## Runtime contract
- An extension type must be declared by the app manifest.
- The container must also hold an approved contract/version for that extension type.
- Validation happens before extension initialization.
- Initialization is idempotent for a `(type,id)` registration.
- Unexpected extension failures are normalized and do not mutate active lifecycle state.
- The app receives only the minimal extension lifecycle context, not platform internals or credentials.

## Governance
Unsupported needs are classified first as either app-specific or a reusable container capability. New extension points/capabilities require explicit approval metadata before being admitted to the contract. Forking/copying the container is never an allowed resolution path.

CC-004-AC01..AC07 are covered by `tests/extensions/cc-004-extension-model.test.mjs`; private module enforcement is also covered by the shared architecture scanner and CI gate.
