# CC-003 — App Capability Contract

Status: IMPLEMENTED against APPROVED / FROZEN requirement.

## Invariant

Learning apps interact with Babysteps only through approved Consumer App Container capabilities:

`App -> Container Capability Contract -> Babysteps`

Direct database, auth-internal, billing-internal, private platform API, or container-private access is prohibited.

## Public contract

App code receives a container-created capability facade and accesses a capability through `src/container/public/capabilities.mjs`. Capability availability is limited to capabilities declared by the resolved app manifest and approved by the container registry.

## Runtime enforcement

- Undeclared capabilities fail with `CAPABILITY_NOT_DECLARED`.
- Unapproved capabilities fail with `CAPABILITY_NOT_APPROVED`.
- Declared but unavailable capabilities fail with `CAPABILITY_UNAVAILABLE`.
- Internal adapter failures are normalized to `CAPABILITY_OPERATION_FAILED`; raw platform errors are not exposed and there is no direct-access fallback.
- Privileged context, service-role secrets, raw auth tokens, billing internals, and DB credentials are never attached to the app-facing facade.

## CI enforcement

Architecture rules fail app builds for container-private imports, Supabase/database access, platform-client internals, and direct Babysteps private/internal/billing endpoint calls.

## Acceptance criteria

CC-003-AC01 through CC-003-AC05 are executable in `tests/capabilities/cc-003-capability-contract.test.mjs` and run in GitHub Actions before merge.
